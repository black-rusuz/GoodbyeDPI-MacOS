# ByeDPI AutoTune Skill for macOS

Этот навык обучает агента автономно тестировать доступность YouTube, диагностировать поведение сетевых пакетов на уровне ТСПУ и подбирать оптимальные комбинации параметров для `ciadpi` (ByeDPI) на macOS без лишних проверочных команд в терминале.

## ⚡ Быстрая справка по окружению (Zero Overhead)

* **Бинарный файл `ciadpi`**: Всегда скомпилирован и находится по пути `build/ciadpi` в корне проекта (также проверяются `./ciadpi` и `/usr/local/bin/ciadpi`). Агенту **не нужно** проверять его наличие (`test -x`, `which`, `ls`) перед запуском.
* **Автономность `autotune/test_config.py`**: Скрипт сам находит свободный порт (по умолчанию 1081+), порождает изолированный процесс `ciadpi`, тестирует все домены из `targets.txt`, выполняет стриминговый бенчмарк реального видео (при `--speed-test`), сохраняет детальные отчёты в `autotune/reports/latest.md` и корректно уничтожает изолированный процесс (SIGTERM/SIGKILL).
* **Файл конфигурации `config`**: Каждая строка — вариант стратегии (пресет). Последняя непустая строка без `#` используется активным сервисом прокси.

## 🛑 Синтаксис флагов: `ciadpi` vs `zapret` / `GoodbyeDPI`

> [!WARNING]
> Конфиги от `zapret`, `winws`, `GoodbyeDPI` **несовместимы** напрямую с `ciadpi`! Запуск с неизвестным флагом мгновенно завершается ошибкой `ciadpi: invalid option -- X` с кодом 254. Агент обязан валидировать флаги по таблице ниже **без запуска тестовых команд**.

### Допустимые флаги десинхронизации в `ciadpi`:
* `-s, --split <pos_t>` — сплит пакета (смещения: `+s` — SNI, `+h` — HTTP host, `+e` — конец, `+m` — середина, например `-s3+s`).
* `-d, --disorder <pos_t>` — split и отправка в обратном порядке (TTL=1 для первого сегмента + retransmit).
* `-o, --oob <pos_t>` — split и отправка байта как Out-Of-Band (TCP Urgent, флаг URG).
* `-q, --disoob <pos_t>` — обратный порядок + OOB данные.
* `-r, --tlsrec <pos_t>` — расщепление записи TLS Record Layer (например `-r1+s`).
* `-m, --tlsminor <ver>` — подмена TLS Minor Version в заголовке ClientHello (например `-m2`).
* `-a, --udp-fake <count>` — количество UDP фейков для подавления QUIC (например `-a1`).
* `-l, --fake-data <path|:str>` — кастомный payload фейкового пакета (файл или `:сырые_байты`).
* `-t, --ttl <num>` — TTL для фейковых пакетов (по умолчанию 8; для YouTube/GGC безопасно строго `2` или `3`).
* `-O, --fake-offset <pos_t>` — смещение начала данных фейка.
* `-Q, --fake-tls-mod <flag>` — модификация фейкового TLS ClientHello: `rand`, `orig`, `msize=<int>`.
* `-e, --oob-data <char>` — кастомный символ OOB (по умолчанию `a`).
* `-A, --auto <t,r,s,n,c>` — автоматический десинк (`torst`, `redirect`, `ssl_err`, `none`, `conn`).
* `-H, --hosts <file|:str>` — список хостов (белый список).
* `-b, --buf-size <size>` — размер сокетного буфера.

### ❌ Запрещённые (несуществующие в `ciadpi`) флаги:
| Неверный флаг | Откуда пришёл | Чем заменить в `ciadpi` |
| :--- | :--- | :--- |
| `-f` / `-f -1` | `zapret` / `winws` | Заменяется на `-l` (fake payload) или убирается, так как чистый split/disorder `-s` / `-d` эффективнее |
| `-Y` | `zapret` | Отсутствует; удалить |
| `-n` | `zapret` (fake host) | В `ciadpi` фейковые домены задаются через файл данных `-l` или модификатор `-Q orig` |
| `-At` / `-Ar` / `-As` / `-An` | Слитная запись `zapret` | В `ciadpi` пишется через пробел: `-A t`, `-A r`, `-A s` |
| `+s` (отдельный аргумент) | Ошибка разделения | Модификатор `+s` пишется слитно с позицией, например `-o1+s` или `-s3+s` |

## 📁 Структура модуля `autotune/`

```text
autotune/
├── targets.txt          # Список ключевых доменов и IP для тестирования
├── test_config.py       # Единый скрипт тестирования метрик и диагностики пакетов
├── test_batch.py        # Пакетный бенчмарк и ранжирование пула стратегий
└── reports/             # Каталог отчётов (под .gitignore)
    ├── .gitkeep
    ├── latest.md        # Результат последнего прогона
    ├── batch_latest.md  # Сводный рейтинг пакетного тестирования
    └── test_*.md        # Исторический архив отчётов
```

## 🚀 Порядок работы агента при подборе стратегии

### Шаг 1. Анализ входных данных (Без терминальных вызовов)
1. Прочитать `config` (или принять строку от пользователя).
2. Отфильтровать несовместимые с `ciadpi` строки по таблице выше без тестовых запусков.
3. Сформулировать гипотезы о влиянии комбинаций флагов на основе `tspu_mechanics.md`.

### Шаг 2. Запуск тестов кандидатов на изолированном порту
Запускать сразу с флагом `--speed-test` для получения полной картины (доступность + пропускная способность CDN):
```bash
python3 autotune/test_config.py --config "<комбинация>" --speed-test
```
> [!IMPORTANT]
> Тестирование с флагом `--config` запускается на отдельном порту (по умолчанию 1081) и **не нарушает работу активного прокси** пользователя на порту 1080. Не требуется запускать фоновые процессы вручную или искать порты.

### Шаг 3. Анализ отчёта и симптомов

| Наблюдаемый симптом в отчёте | Причина на уровне ТСПУ | Что изменить в параметрах стратегии |
| :--- | :--- | :--- |
| `🔴 BLACKHOLE` (0 байт, TLS Handshake = 0 мс) на `googlevideo.com` или `GGC IP` | Буфер ТСПУ склеил пакеты и выделил домен; сессия отправлена в дроп | 1. Добавить `-m 2` (подмена TLS Minor Version)<br/>2. Добавить `-d1+s` (disorder на 1-й байт SNI)<br/>3. Добавить `-r 1+s` (TLS Record Split) |
| `🔴 RST` (TCP Connection reset by peer) | Активный сброс соединения фильтром сигнатур | 1. Добавить OOB-байт: `-o 1+s`<br/>2. Увеличить частоту нарезки SNI: `-s3+s -s6+s -s9+s -s12+s` |
| `🔴 SSL_ERR` при использовании фейка (`-l`) | Фейковый пакет долетел до реального сервера Google GGC | Понизить TTL фейка до `-t 2` или `-t 3`, либо убрать фейк и перейти на чистый сплит/disorder |
| `🟡 SHAPED` или скорость CDN < 300 КБ/с при 100% OK | Множественные флаги `-d` дропаются с TTL=1, стек считает это потерей пакетов и схлопывает TCP CWND | Оставить строго **один** `-d1+s`, остальные позиции перевести на чистый сплит `-s` |

### Шаг 4. Применение победившей стратегии
Если новая стратегия показала результат лучше базового (выше процент доступности, ниже задержка handshake, выше скорость):
1. Продемонстрировать пользователю сводную таблицу сравнения всех протестированных вариантов.
2. Предложить применить лучшую стратегию в `config`.
3. При подтверждении пользователем записать строку в `config`.
