# ByeDPI AutoTune Skill for macOS

Этот навык обучает агента автономно тестировать доступность YouTube, диагностировать поведение сетевых пакетов на уровне ТСПУ и подбирать оптимальные комбинации параметров для `ciadpi` (ByeDPI) на macOS.

## 📁 Структура модуля `autotune/`

```text
autotune/
├── targets.txt          # Список ключевых доменов и IP для тестирования
├── test_config.py       # Единый скрипт тестирования метрик и диагностики пакетов
└── reports/             # Каталог отчётов (под .gitignore)
    ├── .gitkeep
    ├── latest.md        # Результат последнего прогона
    └── test_*.md        # Исторический архив отчётов
```

Справочные материалы навыка:
* [tspu_mechanics.md](./references/tspu_mechanics.md) — физика буфера сборки ТСПУ, TTL-хопы и алгоритмы TCP CUBIC.
* [strategies.md](./references/strategies.md) — проверенные базовые комбинации флагов.

## 🚀 Порядок работы агента при подборе стратегии

### Шаг 1. Запуск базового теста
Агент начинает с проверки текущего активного состояния либо указанного конфига:
```bash
# Проверка текущего запущенного прокси (порт 1080):
python3 autotune/test_config.py --current

# Или проверка конкретной стратегии на изолированном порту 1081:
python3 autotune/test_config.py --config "-m2 -d1 -d1+s -r1+s -s3+s -s6+s -s9+s -a1"
```

### Шаг 2. Чтение и анализ отчёта
Агент читает `autotune/reports/latest.md` и анализирует:
1. **Процент доступности**: сколько из 10 целей вернули `🟢 OK`.
2. **Время TLS Handshake**: задержка завершения ClientHello.
3. **Раздел `Packet Analysis`**: специфические сетевые аномалии.

### Шаг 3. Матрица симптомов и выработка гипотез

| Наблюдаемый симптом в отчёте | Причина на уровне ТСПУ | Что изменить в параметрах стратегии |
| :--- | :--- | :--- |
| `🔴 BLACKHOLE` (0 байт, TLS Handshake = 0 мс) на `googlevideo.com` или `GGC IP` | Буфер ТСПУ склеил пакеты и выделил домен; сессия отправлена в дроп | 1. Добавить `-m 2` (подмена TLS Minor Version)<br/>2. Добавить `-d1+s` (disorder на 1-й байт SNI)<br/>3. Добавить `-r 1+s` (TLS Record Split) |
| `🔴 RST` (TCP Connection reset by peer) | Активный сброс соединения фильтром сигнатур | 1. Добавить OOB-байт: `-o 1+s`<br/>2. Увеличить частоту нарезки SNI: `-s3+s -s6+s -s9+s -s12+s` |
| `🔴 SSL_ERR` при использовании фейка (`-f` / `-l`) | Фейковый пакет долетел до реального сервера Google GGC | Понизить TTL фейка до `-t 2` или `-t 3`, либо убрать фейк и перейти на чистый сплит/disorder |
| `🟡 SHAPED` или скорость CDN < 300 КБ/с при 100% OK | Множественные флаги `-d` дропаются с TTL=1, стек считает это потерей пакетов и схлопывает TCP CWND | Оставить строго **один** `-d1+s`, остальные позиции перевести на чистый сплит `-s` |

### Шаг 4. Тестирование кандидатов на изолированном порту
Агент формирует гипотезу, генерирует модифицированную строку и проверяет её:
```bash
python3 autotune/test_config.py --config "<новая комбинация>" --speed-test
```
> [!IMPORTANT]
> Тестирование с флагом `--config` запускается на отдельном порту (по умолчанию 1081) и **не нарушает работу активного прокси** пользователя на порту 1080.

### Шаг 5. Применение победившей стратегии
Если новая стратегия показала результат лучше базового (выше процент доступности, ниже задержка handshake, выше скорость):
1. Агент демонстрирует пользователю сравнение результатов из отчёта.
2. Предлагает применить новую стратегию в `config`.
3. При подтверждении пользователем записывает строку в `config`.
